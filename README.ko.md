# AlphaEvolve Plugin

[English](README.md) | **한국어**

Google DeepMind의 **AlphaEvolve**와 오픈소스 **OpenEvolve** 구조를 따라 만든 진화형 알고리즘 탐색·코드 최적화 플러그인입니다.
Claude Code와 Antigravity에서 쓸 수 있습니다.

## 설치

**Claude Code**
```
/plugin marketplace add bakeyeon/alphaevolve-plugin
/plugin install alphaevolve@alphaevolve-plugin
```

**Antigravity**: 저장소를 플러그인으로 추가하면 됩니다. 루트의 `plugin.json`을 사용합니다.

## 주요 기능

1. **에이전트 기반 진화 루프 (Mode A)**
   - 별도 패키지나 API 키 없이 에이전트가 직접 변이를 제안합니다.
   - `evolve_local.py`가 후보를 평가하고 `archive.json`과 `best_program.py`를 관리합니다.
   - 명령은 `init`, `sample`, `evaluate`, `status` 네 가지입니다.
2. **OpenEvolve CLI 연동 (Mode B)**
   - `pip install openevolve`와 바로 호환되는 `initial_program.py`, `evaluator.py`, `config.yaml`을 만듭니다.
3. **믿을 수 있는 평가기 템플릿**
   - 정답 기준(정확한 DP)과 비교해 정확성을 판정합니다.
   - 시드를 고정한 무작위 인스턴스 40개와 경계 사례로 테스트합니다.
   - 후보마다 별도 프로세스에서 실행하고 시간 제한을 둡니다.
   - 점수(`combined_score`)는 항상 같은 값이 나오게 품질만 반영합니다. 실행 시간은 중앙값으로 따로 기록합니다.

## 내 문제에 이 플러그인이 맞을까?

프로그래밍을 몰라도 됩니다. 문제를 평소 말로 설명하면 에이전트가 코드와 채점 스크립트를 만들고 루프를 돌립니다.
여러분이 가져올 것은 도메인 지식입니다. 어떤 답이 좋은 답인지, 어떤 답은 허용되지 않는지를 알려 주면 됩니다.

**한 줄 요약.** 여기서 말하는 진화는 "레시피를 여러 가지로 바꿔 보고, 하나씩 맛보고, 제일 나은 걸 남기는 일을 반복"하는 것입니다.
맛보기가 자동으로, 빠르게, 공정하게 되어야만 통합니다. 그래서 세 가지를 물어보세요.

1. **짧은 스크립트가 시도마다 점수를 숫자로 매길 수 있나요?** (클수록 좋음: 빈 칸이 적다, 비용이 낮다, 더 빠르다, 고정된 테스트셋에서 정확도가 높다)
2. **그 스크립트가 답이 규칙을 지키는지 확인할 수 있나요?** (규칙 위반이 없다, 믿을 수 있는 느린 버전과 결과가 같다)
3. **채점 한 번이 몇 시간이 아니라 몇 초 안에 끝나나요?** 진화는 수십에서 수백 번 시도합니다.

셋 다 "예"면 이 플러그인이 잘 맞습니다. 하나라도 "아니오"면 보통 더 간단한 방법이 낫습니다.

### 잘 맞는 경우

| 분야 | 쉬운 말로 한 문제 | 점수 | 꼭 지켜야 할 규칙 |
|---|---|---|---|
| 실험 생물학 | 반복 샘플과 대조군이 고르게 퍼지도록 96웰 플레이트에 샘플 배치 | 제약 위반 수가 적고 균형이 좋을수록 | 모든 샘플이 정확히 한 번 배치 |
| 모든 실험실 | 공용 장비(시퀀서, 현미경) 예약 요청 여러 건 배정 | 총 대기 시간 | 중복 예약 없음, 마감 준수 |
| 언어학, NLP | 큰 말뭉치에서 너무 느린 텍스트 정제·토큰화 함수 | 고정 샘플에서 실행 시간 | 지금 함수와 출력이 똑같음 |
| 생물정보학 | 파이프라인의 병목인 직접 만든 서열 점수 함수 | 실행 시간, 메모리 | 원래 함수와 점수가 같음 |
| 운영, 물류 | 현장 조사 방문지나 배송 경로 짜기 | 총 이동 거리 | 모든 장소 방문, 시간대 준수 |
| ML 학습 | 길이가 제각각인 시퀀스를 패딩이 최소가 되도록 배치에 묶기 | 패딩 비율, 에폭당 배치 수 | 모든 시퀀스 한 번씩 사용, 배치 크기 제한 |
| ML 학습 | 데이터 전처리 단계나 직접 만든 레이어 하나 빠르게 하기 | 고정된 작은 입력에서 실행 시간과 최대 메모리 | 기준 코드와 출력이 같음 |

**대규모 학습 코드.** 학습 전체를 진화시킬 수는 없습니다. 평가 한 번에 몇 시간씩 걸리기 때문입니다.
대신 느린 부분 하나(전처리 단계, 배치 묶는 규칙, 직접 만든 연산 하나)를 떼어 내고, 고정된 작은 입력을 주고,
결과가 같은지 확인하면서 속도와 메모리를 몇 초 안에 채점합니다. 평가기 템플릿은 실행 시간을 잽니다.
메모리는 에이전트에게 최대 메모리 지표를 추가해 달라고 하세요(예: `tracemalloc`, GPU라면 `torch.cuda.max_memory_allocated`).
그다음 개선된 부분을 전체 학습 코드에 다시 넣고 실제로 빨라졌는지 확인합니다.

### 굳이 안 써도 되는 경우

| 상황 | 진화가 도움이 안 되는 이유 | 대신 쓸 것 |
|---|---|---|
| 이미 방법이 알려진 표준 작업(정렬, 최단 경로, 선형 회귀, 서열 정렬) | 전문가들이 이미 최선의 방법을 찾아 둠 | 기존 라이브러리. 어떤 걸 쓸지 에이전트에게 물어보세요 |
| 숫자 몇 개 조정(학습률, 임계값) | 코드가 아니라 숫자를 찾는 문제 | 그리드 탐색이나 Optuna 같은 튜너 |
| 자동 점수가 없음(글의 완성도, 그림 디자인, "이 가설이 흥미로운가") | 시도끼리 비교할 기준이 없음 | 에이전트에게 바로 묻고 직접 판단 |
| 평가 한 번에 몇 분에서 몇 시간(학습 전체, 밤새 도는 시뮬레이션, 실제 실험) | 수백 번 시도하면 몇 주가 걸림 | 먼저 빠른 축소 문제로 바꾸거나 직접 최적화 |
| 코드가 틀리거나 멈춤 | 진화는 돌아가는 코드를 개선할 뿐 버그를 고치지 않음 | 에이전트에게 버그 수정 요청 |
| 한 번만 돌릴 스크립트 | 몇 초 아껴도 의미 없음 | 돌아가는 가장 간단한 버전 |

### 프로그래밍을 몰라도 시작하는 법

1. 문제를 설명합니다: *"샘플 300개를 96웰 플레이트에 배정해. 같은 샘플의 반복은 같은 플레이트에 두면 안 되고, 플레이트마다 대조군이 4개 필요해. 플레이트끼리 최대한 균형 있게 해 줘."*
2. 에이전트가 단순하고 확실히 맞는 버전(L1)과 채점 스크립트를 만듭니다.
3. **채점 스크립트는 직접 확인하세요.** 예시 답 몇 개와 점수, 규칙 검사 결과를 보여 달라고 하세요. 나쁜 답이 좋은 점수를 받으면 알려 주세요. 진화는 점수만 쫓아갑니다.
4. Mode A 루프를 돌리고, `best_program.py`와 점수 기록을 에이전트와 함께 읽습니다.

## 추천 흐름: 3단계 다음에 진화

1. **L1 기본**: 정의를 그대로 옮긴, 확실히 맞는 코드. 평가기의 정답 기준이 됩니다.
2. **L2 깔끔**: 읽기 좋고 실용적인 알고리즘
3. **L3 최적**: 직접 유도할 수 있는 가장 좋은 방법
4. **진화**: L3보다 더 나은 답을 탐색하고 싶을 때만 씁니다. 점수를 코드로 계산할 수 있는 문제여야 합니다.

- *"휴리스틱 점수를 극대화하도록 함수를 진화적으로 개선해 줘"*

## 로컬 진화 코드 한눈에 보기

Mode A에서는 스크립트 세 개가 일을 나눕니다. `scaffold_evolve.py`는 작업 폴더를 한 번 만들고,
`evaluator.py`는 프로그램 하나를 채점하고, `evolve_local.py`는 모든 시도의 기록을 남기며 어느 것이 최고인지 정합니다.
새 프로그램은 에이전트가 쓰고, 이 스크립트들은 판정과 기록만 합니다.

**`scaffold_evolve.py`**
- `scaffold(target_dir, task_name)`: 템플릿 파일 네 개를 새 작업 폴더에 복사하고 `candidates/`를 만듭니다. 이미 있는 파일은 건너뛰어서 직접 고친 내용을 덮어쓰지 않습니다.

**`evaluator.py`**
- `make_instances(seed, n)`: 테스트 세트를 만듭니다. 시드를 고정한 무작위 문제 n개와 정해진 경계 사례입니다. 시드가 같으니 모든 후보가 같은 문제로 시험받습니다.
- `reference_solve(items, capacity)`: 진짜 최적값을 주는 믿을 수 있는 느린 풀이(정확한 DP)입니다.
- `evaluate(program_path)`: 후보 하나를 별도 프로세스에서 시간 제한을 두고 실행하고, 규칙을 어긴 답이 하나라도 있으면 탈락시키고, 지표를 돌려줍니다: `combined_score`, `valid`, `optimality_ratio`, `optimal_fraction`, `runtime_ms`, `complexity`.
- `_fail(error)`: 탈락한 후보의 지표입니다(점수 0, `valid` 0, 탈락 이유).

**`evolve_local.py`** (명령)
- `init` (`cmd_init`): `initial_program.py`를 `gen_000`으로 채점하고 새 `archive.json`을 시작합니다.
- `sample` (`cmd_sample`): 다음에 변형할 부모를 추천합니다. 최고 점수 후보들(exploit)과 크기가 다른 프로그램 최대 두 개(explore)를 함께 줘서 한 아이디어에 갇히지 않게 합니다.
- `evaluate` (`cmd_evaluate`): 새 후보를 `candidates/`에 복사해 채점하고, 부모와 변경 이유와 함께 기록하고, `delta_vs_parent`를 알려 줍니다(양수면 변경이 도움이 됨).
- `status` (`cmd_status`): 최고 세대와 모든 세대의 한 줄 기록을 보여 줍니다.

**`evolve_local.py`** (보조 함수)
- `load_evaluator(workspace)`: 작업 폴더에 있는 `evaluator.py`를 불러옵니다.
- `load_archive` / `save_archive`: `archive.json`을 읽고 씁니다.
- `_update_best(workspace, archive)`: 점수가 가장 높은 유효한 세대를 찾아 `best_program.py`로 복사합니다. 점수가 같으면 먼저 나온(보통 더 단순한) 프로그램이 이깁니다.
